Bob Logbook
A git shadow-branch AI workspace for IBM Bob

The Problem

When a developer uses IBM Bob, the valuable context — decisions made, prompts that worked, constraints discovered — lives only in the chat window and disappears when the session ends. Teammates cannot pick up where someone left off without reading the entire chat history. There is no persistent, structured, conflict-free record of what Bob helped build.

"As a developer using IBM Bob, I want my AI session context captured automatically in git so my teammate can pick up exactly where I left off — without reading the entire chat history."

The Solution

🔁 Auto-capture hooks

Bob's Stop and UserPromptSubmit lifecycle hooks fire on every turn. A Python wrapper reads the JSON payload and appends a timestamped entry to the shadow branch. Zero developer interaction required.

🌿 Git shadow branch

All log entries live on an orphan branch bob-context — no shared history with main, so there are never merge conflicts. Git is the safety net: nothing is ever lost, full rollback via git log.

🐍 bob_log.py CLI

Python 3 stdlib only. Commands: init, read, write, append, ls, commit, export. Git plumbing — no branch switching, never touches the working tree.

🌐 Single-file viewer

viewer.html — drag-and-drop a JSON export, see a browsable workspace: file tree sidebar + timeline cards per author + plain Markdown renderer. No server, no npm, opens anywhere.

What makes it novel

Dogfoods Bob

Built entirely using Bob — the planning, the CLI, the viewer, the tests, and this PDF. The tool proves itself.

Shadow branch pattern

An orphan git branch as AI working memory is a genuinely new technique — not a database, not a cloud service, just git.

Zero friction

Install once. After that, every Bob session is captured automatically. No forms to fill, no commands to run, no accounts needed.

• Shell has real limits here. Git plumbing with subdirectories, error handling, and path sanitisation gets gnarly fast in shell. Python is the right call: stdlib only (subprocess, pathlib, json, os), no compilation, readable, and the judges can follow it easily.

Go would be cleaner long-term but the boilerplate and cross-compilation story adds friction you don't need today.

2 · Git Plumbing — bob_log.py append

The core trick: write to the shadow branch without ever switching branches. Uses four git plumbing commands in sequence — the working tree is never touched.

bob_log.py — _write_blob() git plumbing flow
def _write_blob(path: str, content: str, repo: Path) -> None:
    # 1. Hash the content into the git object store
    blob = run(["git", "hash-object", "-w", "--stdin"],
               input=content, capture_output=True, text=True, cwd=repo).stdout.strip()

    # 2. Read the current shadow-branch tree and inject the new blob
    tree_in = run(["git", "ls-tree", "bob-context"],
                  capture_output=True, text=True, cwd=repo).stdout
    tree_in += f"100644 blob {blob}\t{path}\n"

    # 3. Write the updated tree object
    new_tree = run(["git", "mktree"],
                   input=tree_in, capture_output=True, text=True, cwd=repo).stdout.strip()

    # 4. Create a commit on top of the current shadow-branch HEAD
    parent  = run(["git", "rev-parse", "bob-context"],
                  capture_output=True, text=True, cwd=repo).stdout.strip()
    commit  = run(["git", "commit-tree", new_tree, "-p", parent, "-m", f"log: {path}"],
                  capture_output=True, text=True, cwd=repo).stdout.strip()

    # 5. Advance the shadow-branch ref — working tree untouched
    run(["git", "update-ref", "refs/heads/bob-context", commit], cwd=repo)

3 · Viewer Rendering — viewer.html

Accepts a JSON export ({ files: { "chat/author.md": "..." } }). Files under chat/ → timeline renderer. All others → Markdown renderer. No server, no npm.

viewer.html — JSON load + route
function loadExport(json, fileName) {
  _files = json.files || {};
  buildSidebar(_files);

    Object.keys(_files).find(p => p.startsWith('chat/'))

function openFile(path) {
  const isChat = path.startsWith('chat/');
  panel.innerHTML = isChat
    ? renderTimeline(parseChatEntries(_files[path]), path)
    : renderMarkdown(_files[path], path);
}

Test Suite — test_bob_log.py

Python unittest, zero external dependencies. Each test case creates a fresh git init temp directory and tears it down on completion.

test_bob_log.py — test cases
class TestBobLog(unittest.TestCase):

  def setUp(self):
    self.repo = tempfile.mkdtemp()
    subprocess.run(["git","init"], cwd=self.repo)
    subprocess.run(["git","config","user.email","t@t.local"], cwd=self.repo)
    subprocess.run(["git","config","user.name","Test"], cwd=self.repo)

  def test_init_creates_branch(self):
    bob_log.cmd_init(self.repo)
    result = subprocess.run(["git","rev-parse","bob-context"],
                              cwd=self.repo, capture_output=True)
    self.assertEqual(result.returncode, 0)

  def test_write_then_read(self):
    bob_log.cmd_init(self.repo)
    bob_log.cmd_write("notes.md", "hello world", self.repo)
    out = bob_log.cmd_read("notes.md", self.repo)
    self.assertIn("hello world", out)

  def test_append_accumulates(self):
    bob_log.cmd_write("log.md", "line1\n", self.repo)
    bob_log.cmd_append("log.md", "line2\n", self.repo)
    out = bob_log.cmd_read("log.md", self.repo)
    self.assertIn("line1", out); self.assertIn("line2", out)

  def test_working_tree_untouched(self):
    bob_log.cmd_write("secret.md", "data", self.repo)
    self.assertFalse((Path(self.repo) / "secret.md").exists())

How to Run

1 · Install (one-time)

git clone <repo> ~/projects/ibmbob
cd ~/projects/ibmbob
python3 bob_log.py init       # creates bob-context branch

2 · Configure Bob hooks

cp .bob/settings.json  ~/.bob/settings.json
# or place in .bob/ of any project workspace

3 · Use Bob normally

Every turn is auto-captured. To inspect or export:

python3 bob_log.py ls           # list files on shadow branch
python3 bob_log.py read chat/jaminleod.md
python3 bob_log.py export       # writes bob-context-export.json

4 · View in browser

open viewer.html
# drag bob-context-export.json onto it
# or open viewer.html?demo for sample data
